# Database tests refuse non-throwaway databases; CI fails if they skip

## What was done
First change from the reviewer's findings (P1), which the operator approved:
- `tests/conftest.py` holds the shared `db` fixture. It wipes the public schema, so it now
  refuses any `LENS_TEST_DB_URL` whose database name does not contain "test"
  (`assert_throwaway`).
- With `LENS_REQUIRE_DB_TESTS=1`, set in `.github/workflows/roadmap.yml`, a missing URL or
  driver fails the run instead of skipping it.
- `test_hosted_roles_and_strangers_get_nothing` now checks SELECT, INSERT, UPDATE and DELETE,
  and restores default privileges in `finally`.
- Verified locally:
  - the normal run skips the 3 database tests;
  - require mode errors on them;
  - a URL naming `postgres` is refused before connecting.

## What was found / decided
Before this, `tests/test_spine.py` dropped the public schema of whatever database the variable
named. One mistaken URL (for example the PROVES Supabase) would have wiped it.

## Lessons
A destructive test fixture needs a guard on its target, not just on whether a target exists.
